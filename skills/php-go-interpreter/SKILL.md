# Go製PHPインタプリタの開発

目的は、対象バージョンと機能を限定したPHP処理系をGoで作り、公式PHPとの比較で動作を確認すること。PHPアプリケーションをGoへ翻訳する作業とは区別する。ユーザーへの説明とプロジェクト文書は日本語を基本とする。

## 連続実装の単位

機能開発では最初に[まとめて実装する進め方](references/batch-development.md)を読み、依頼された段階・到達目標を作業単位とする。小機能の実装ごとに最終報告で停止せず、実装・対象テスト・不具合修正を繰り返して同じ依頼の残作業へ進む。全段階を依頼された場合は依存順に段階をまたいで続ける。

公式比較の環境エラーは、独立して進められる実装の停止条件にしない。比較待ちを記録し、比較可能になった時点または段階の節目にまとめて検証する。実装済み・ローカル検証済み・公式比較済み・統合動作確認済みを区別する。レビューや文書更新だけの依頼では、その範囲を維持する。

リリース準備もまとめて依頼された場合は、同じ参照文書の「リリース準備をまとめて依頼された場合」に従い、差分整理・再構築・CI整備・許可済みのGitHub保存まで続ける。

「全検証を一括」「確認フローなしで検証」「リリースまでまとめて」の依頼では、[一括検証と公開](references/batch-verification.md)を読む。工程ごとのユーザー確認を省き、証拠確認・検証・修正・文書整理を連続して行う。スキルやプロンプトの作成だけの依頼では実検証・公開を開始しない。

## 対象と最初の実装

- 作業ディレクトリの既存コードと設定を確認する。すでに対象バージョン、CLI、設計があればそれを維持する。
- 対象PHPはユーザーの指定を優先する。未指定なら、利用可能な公式PHPのバージョンを確認して採用理由を伝え、メジャー・マイナーと検証に使用するパッチバージョンを記録する。環境がない場合は比較用環境を準備できる範囲で進め、実比較の未実施を明記する。PHPを確認できたことにしない。
- 新規開発時は `docs/compatibility.md` に対象バージョン、対応済み・未対応の機能、CLI仕様、比較コマンドを記録する。未決定事項を既決定として記載しない。
- 初期範囲の候補は `<?php`、コメント、整数・文字列・真偽値・null、変数の代入と参照、`echo`、括弧、整数の四則演算、文字列連結。ユーザーが範囲を指定していればそちらを優先する。演算を追加した時点で必要になる浮動小数点値やゼロ除算の扱いも定義する。
- 条件分岐、ループ、関数、配列、クラスは段階的に追加する。標準関数、C拡張互換、Webサーバー、JITは依頼があってから対象に含める。

## 実装上の判断

新規の最小実装では、字句解析→構文解析→AST評価を基本とする。VMは性能や設計上の必要が出たときに検討する。CLIはPHPファイルのパスを受け取り、プログラム出力をstdout、診断をstderrへ出す。ビルド済みの実行ファイルで比較し、Goのコンパイル出力をPHPの実行結果に混ぜない。

- 値はPHPの型を識別できる表現にする。Goの型変換や比較を、そのままPHPの規則として流用しない。
- 優先順位、結合規則、型変換、数値精度、文字列のエスケープは対象バージョンの公式PHPで確認する。変数未定義や構文エラーも検証する。
- 配列を追加するときは順序、キーの変換、コピーと参照を考慮する。GoのmapだけではPHPの配列の挙動を再現できない。
- 未対応の構文や演算は明確な診断と非ゼロ終了で拒否する。無視して実行成功扱いにしない。診断文言の完全互換を目指すかは対応範囲に記録する。
- 既存のPHPインタプリタを呼ぶだけの実装を、Goによる処理系の実装として扱わない。公式PHPは比較の基準として使う。

## 公式PHPとの比較

このプロジェクトの比較用環境はPHP 8.3・8.4・8.5のPodmanコンテナを使用する。構成と起動手順は [コンテナ構成の案内](../../containers/php-version/README.md) にある。配置先は `/Users/kouji/docker/php-version`、実行用ラッパーは同ディレクトリの `bin/php83`、`bin/php84`、`bin/php85`。起動済みかを確認してから比較する。複数バージョンを比較しても、Go実装が準拠する対象バージョンは明示し、バージョン間の仕様差をGo実装の不具合と混同しない。

対応機能ごとに小さいPHPファイルを用意し、Go実装と公式PHPへ同じファイルを渡す。成功例に加え、優先順位、境界値、型変換、診断を検証する例を選ぶ。正常終了するはずのfixtureが両方でエラーになっている場合は、一致していても成功テストと見なさない。

比較には [scripts/compare_php.py](scripts/compare_php.py) を使える。Python 3の標準ライブラリのみを使用する。作業ディレクトリはプロジェクトのルートに揃える。以下のバージョンとパスは、実際に採用したものに置き換える。

```sh
python3 skills/php-go-interpreter/scripts/compare_php.py \
  --php /path/to/php \
  --php-version 8.3.0 \
  --fixtures tests/fixtures \
  --interpreter ./bin/gophp '{file}'
```

スキルを別の場所へ移した場合は、スクリプトのパスも読み込んだSKILL.mdの場所に合わせる。`--interpreter` は最後に置き、`{file}` を独立した引数として1つ指定する。タイムアウトは `--timeout` で秒数を指定する。

このスクリプトはphp.iniを読み込まず、エラー表示先をstderr、ログ出力を無効、タイムゾーンをUTCに揃える。各fixtureを独立したプロセスで実行し、stdinは空にする。stdout、stderrをバイト単位で比較し、終了コードも比較する。終了コード0は全件一致、1は不一致、2は環境・入力・タイムアウト等の検証エラー。外部入力や拡張に依存するfixtureは、必要な環境を明示した別のテストとして用意する。

差異が出たら最小の再現例を残し、公式PHPの結果を基準に原因を絞って修正する。出力のtrim、警告の削除、終了コードの無視で差異を隠さない。診断の既知の差異などを許容する場合は、理由と対象テストを記録し、完全一致と分けて報告する。乱数、時刻、絶対パス等に依存するテストは環境を制御する。

変更に応じてGoのテストと比較テストを実行し、対象バージョン、対応した機能、比較件数、一致・不一致、未実施項目を報告する。比較を実行できない場合も実装とテスト準備は進め、実行済みの検証と区別する。完全互換という表現は、限定した対応範囲を超えて使わない。
