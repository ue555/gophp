# 一括検証と公開

## 範囲と実行方針

「確認フローなし」は工程ごとの継続許可を求めない意味であり、レビュー・テスト・証拠確認を省く意味ではない。対象アプリ、固定PHP版、完成条件は依頼と現行文書から確定する。件数・タグ・成功状態をこのスキルに固定しない。

依頼内で必要な修正と再検証は続け、進捗だけを共有する。実装、ローカル検証、公式比較、実HTTP、CI、公開を別々の状態で記録する。新しい機能や依存更新を完成条件に追加しない。commit・push・タグは、その依頼で明示許可された場合だけ実施する。

## 検証の順序

1. **現状と証拠**：Git状態・差分、fixtureと期待値の対応、版別生ログと終了コードを照合する。過去の成功は変更後の成功へ転用しない。実行時のコミット、未コミット差分の識別情報、バイナリハッシュ、lock、対象版を記録する。
2. **保存対象**：DB・環境設定・秘密情報・vendor・キャッシュ・生成バイナリの除外を確認する。手動DBと既存成果を削除しない。秘密情報を発見した場合、値を出力せず、該当ファイルの公開を止めて解決する。実測ログの出力を成功に見せる目的で加工しない。
3. **再構築**：新規チェックアウト相当の独立ディレクトリへ今回の未追跡ファイル・実行権・symlinkも含む候補を配置する。固定lockから依存を新規導入し、必要なCライブラリ、初期manifest、空DB・キャッシュから起動できるか確認する。既存vendorやmanifestをコピーした検証は、依存取得の再現成功とは区別する。
4. **ローカル回帰**：既存Makefile等でGo・Pythonテスト、vet、ビルド、差分検査を行う。skipや依存未導入を確認し、必須テストが省略されたまま全検証成功としない。
5. **公式比較**：対象PHPのパッチ版を実行して確認し、版ごとに全fixtureのstdout・stderr・終了コードを既存比較器で比較する。期待件数と個別結果も照合する。環境エラーは不一致と分ける。
6. **アプリ統合**：新規アプリの公式PHP／Goの実TCP・DB比較と、既存固定アプリの回帰を実行する。既存スクリプトとHTTP契約を利用し、要求件数・継続／並行条件・日時の扱いを維持する。各runtime・版でDB・storage・bootstrapキャッシュを分離する。終了時は自分が起動したサービスと一時データだけを片付ける。
7. **CI整備**：新規依存導入、上記の必須回帰・版別比較・アプリ検証をCIへ接続する。Docker／Podmanの差、ホストとコンテナのパス、権限、必要な拡張を確認する。環境差への対応は検証スクリプトで扱い、検証項目を削って成功させない。失敗時にも生ログ・比較成果物を保存する。
8. **修正と記録**：差異は最小再現にして原因を修正し、影響する対象テストから再検証する。共有基盤を変更した場合は全回帰を再実行する。変更・失敗・未確認の懸念がなければ成功済みの大規模検証を理由なく繰り返さない。現在の状態をREADME・進捗・証拠一覧へ反映する。

## 公開まで許可されている場合

公開対象を選んでコミットし、通常pushする。リモートコミットSHAとCIのhead SHAを照合して全必須ジョブの完了を確認する。失敗はログから修正し、新しいコミットで再実行する。修正後のSHAへ古いCI成功を流用しない。

タグ付けも許可されていれば、ローカル・リモート双方で未使用の版番号を選び、成功したコミットに注釈付きタグを作成してpushする。既存タグ・履歴は上書きしない。タグの参照先、リモートブランチ、作業ツリーを最後に確認する。公開後に追跡文書を変更した場合は未コミットのまま「クリーン」と報告せず、最終SHAとの関係を記録する。

公開許可がなければ、CI設定の準備とローカル確認まで行い、GitHub上のCIは未実施とする。スキルの自動選択を公開許可に読み替えない。

## 環境障害と完了判定

Podman接続、TCP bind、依存取得、Git書き込み、GitHub接続は必要時に実測する。接続拒否を確認した後は、状態変化なしに同じ試行を繰り返さず、独立して進められる検証・修正・CI準備を終える。権限を自動で弱めたり、VMを再起動したりしない。

コマンド・実際の終了コード・生ログを実行ごとの固有パスへ保存する。パイプの終了コードとサーバー後片付けの終了コードを混同しない。CI起動のみ、集計のみ、ユーザー報告のみの証拠はそれぞれ区別する。

全必須検証が成功し、許可された公開作業も完了した場合だけ依頼全体を完了とする。外部要因で残る場合は、成功／失敗／未実施の表と、そのまま再実行できるコマンドを残す。スキルの変更自体は自動再開の機構ではなく、継続Goalの操作は明示依頼と利用可能な機構の規則に従う。
