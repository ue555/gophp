## 実装した範囲

以下はGo側で実装・テストした機能です。項目4〜8の124fixtureを追加し、既存213件を維持しています。
ユーザー提供の公式PHP比較で判明した4種類・延べ6件の差分を修正しました。
修正後のユーザー提供ログで全3版とも337件一致し、既存213件を含む回帰比較も完了しています。
公式PHPの実比較と、エージェント側の保存済み期待値によるローカル検証を区別して記録しています。

| 分類 | 対応範囲 |
| --- | --- |
| ファイル | 先頭の `<?php` と直後の空白、末尾の省略可能な `?>`、LF/CRLF/CRの行数計算 |
| コメント | `//`、`#`、`/* ... */` |
| リテラル | 10進整数、10進浮動小数点・指数表記、文字列、true/false/null |
| 変数・代入 | 値の参照、再代入、式内代入、右結合の連鎖/複合代入、前置/後置の増減。変数名は大小文字を区別 |
| 文 | `echo 式, 式;`、式文、空文、ブロック、波括弧付き/単文の `if / elseif / else if / else`、ネスト、`while / for / do while`、レベル付き `break / continue`、`return` |
| 演算 | 二項 `+ - * / % . < <= > >= == != <> <=> === !== && \|\|`、単項 `+ - ! ++ --`、`+= -= *= /= %= .=`、括弧 |
| 条件 | 基本型・配列・オブジェクトのPHP真偽値変換、選択された分岐だけの評価、論理演算の短絡評価 |
| 文字列 | 単一・二重引用符、複数行、UTF-8を含むバイト列 |
| 配列 | `[]` / `array()`、int/stringキー、添字読み書き、`[]` 追加、ネスト、値コピー、結合 `+`、比較 |
| 通常の関数 | 定義/呼び出し、位置引数・既定値、値渡し、return/null、ローカルスコープ、再帰、宣言位置、診断 |
| オブジェクト | `stdClass`、独自の `class`、プロパティ、メソッド、コンストラクタ、`$this`、アクセス制御、共有、比較 |
| 診断 | 未定義変数/キー/プロパティ、変換警告・非推奨、ゼロ除算、型エラー、アクセス違反、呼び出し履歴、構文・コンパイルエラー |

ファイル先頭のHTML・BOM・短縮開始タグは対象外です。終了タグの直後は改行1つまでを許し、
それ以降のテキストやPHPブロックは拒否します。終了タグは文末のセミコロンを兼ねます。
終了タグを使わないecho・代入・式文にはセミコロンが必要です。if文の閉じ波括弧には不要です。

優先順位は高い順に、増減 `++ --`・単項 `+ -`、`!`、乗除算/剰余、加減算、連結、大小比較 `< <= > >=`、
等価/三方比較 `== != <> === !== <=>`、`&&`、`||`、代入 `= += -= *= /= %= .=` です。
添字・プロパティ・メソッド呼び出しは単項演算より先に結び付きます。
算術・連結演算は左結合で、`'sum=' . 2 + 3` は `sum=5` になります。
`&&` と `||` もそれぞれ左結合です。`true || false && false` は `true || (false && false)`、
`!0 + 2` は `(!0) + 2` として解析します。
大小比較と等価比較はそれぞれ非結合です。同じグループの括弧なしの連鎖
`1 < 2 < 3`、`1 == 1 !== false` は構文エラーです。
`(1 < 2) < 3` の明示的な括弧や、優先順位が異なる `1 < 2 === true` は許可します。
代入は右結合です。`$a = $b = 3`、`echo $a = 3;`、`if ($a = 1)` を受け付け、代入した値を返します。
PHPの代入文法に合わせて、`false || $a = 7` は `false || ($a = 7)` になります。
変数・配列添字・オブジェクトプロパティへ代入でき、非書き込み式への代入や参照代入は拒否します。

値はint64・float64・string・bool・null・順序付き配列・オブジェクトを区別して保持します。
整数の加減乗算で範囲を超えた場合、演算の両項をfloat64に変換して計算します。
除算は両項が整数で割り切れる場合は整数、それ以外はfloat64です。
最小整数を-1で割った場合もfloat64になります。
ゼロ（false、null、数値文字列のゼロ、-0.0を含む）による除算は診断を出して255で終了します。

数値文字列は10進数として扱い、前後のASCII空白・符号・小数・指数を認識します。
数値に続く余分な文字には警告を出し、数値部分で演算します。
数値で始まらない文字列の四則演算はTypeError相当の診断で終了します。
演算時はtrueを1、false/nullを0に変換します。
出力・連結ではtrueを `1`、false/nullを空文字列に変換します。
浮動小数点の文字列化はPHPの既定precision=14を目標とし、指数表記、INF/NAN、負のゼロを扱います。
以前のユーザー提供ログに含まれるfixtureでは、丸め・警告位置も含めて一致しました。
未収録の入力での厳密な互換性は未確認です。PHP 8.5のNaNから文字列への変換警告は、
ユーザー提供ログの `compound_nan_string.php` で版差も含めて一致しました。
バージョン別の診断対応にはif条件・論理演算の真偽値変換と、配列キーの変換を含みます。

単一引用符では `\\` と `\'` のみ展開し、その他のバックスラッシュを保持します。
二重引用符では `\n \r \t \v \e \f \\ \" \$`、1〜2桁の16進エスケープ、
1〜3桁かつ255以下の8進エスケープを展開します。未知のエスケープは保持します。
文字列中の変数展開、Unicodeコードポイントエスケープ、255を超える8進エスケープは拒否します。

### 厳密比較・真偽値変換・条件分岐

`===` は型と値の両方を比較し、結果をboolで返します。`!==` はその否定です。
数値文字列も型変換しません。`1 === '1'`、`1 === 1.0`、`false === null` はfalseで、
`'01' === '1'` もfalseです。文字列はバイト列で比較します。
float同士では `0.0 === -0.0` はtrue、NaNは自身との比較でもfalseです。
比較の両オペランドは評価されるため、`false === (1 / 0)` はゼロ除算になります。
仕様の確認には[公式の比較演算子の説明](https://www.php.net/manual/en/language.operators.comparison.php)と
[PHP 8.4.26の厳密比較実装](https://github.com/php/php-src/blob/php-8.4.26/Zend/zend_operators.c#L2273)を使用しました。

### 大小比較・緩い比較

`< <= > >= == != <>` は結果をboolで返します。`<>` は `!=` と同じです。
`<=>` は比較結果をintの-1・0・1で返し、等価比較と同じ非結合グループに属します。
対応型はint・float・string・bool・null・配列・オブジェクトです。基本型では算術の数値変換とは分けて、次の順序で型の組み合わせを判定します。

| 組み合わせ | 比較方法 |
| --- | --- |
| nullとstring | nullを空文字列として比較。`null == ''` はtrue、`null == '0'` はfalse |
| boolを含む、または上記以外のnull | PHPの真偽値規則で比較。falseがtrueより小さい。`null < -1` はtrue |
| int同士 | int64のまま比較し、大小判定で減算による桁あふれを起こさない |
| intとfloat、float同士 | float64で比較。大きなintがfloatへ丸められ同値となる場合もPHPに合わせる |
| string同士 | 両方が数値文字列なら数値比較。それ以外は元のバイト列の辞書順 |
| 数値とstring | 全体が数値文字列なら数値比較。それ以外は数値を文字列化して辞書順で比較 |

数値文字列には前後のASCII空白・符号・小数・指数表記を許します。
`'10tail'` のような先頭だけ数値の文字列は、比較では数値文字列として扱わず、変換警告も出しません。
文字列同士では、int64を超えた整数文字列の精度喪失や同符号のINFへの変換を検知し、
PHPの規則に従って元の文字列の辞書順へ戻します。数値と文字列の比較にはこの補正を適用しません。

NaNと数値・文字列の比較では `!=` / `<>` がtrue、`== < <= > >=` はfalseで、`<=>` は1です。
NaNとbool/nullの組み合わせは真偽値の比較規則を使います。
この比較処理は8.5でもNaN変換警告を出しません。`elseif ($nan)` や `!$nan` の
実際の真偽値変換で出す警告とは区別します。

比較の部分式は左から評価します。単独の変数オペランドはPHPの比較命令に合わせて部分式の評価後に読み、
`>`・`>=` は内部でオペランドが入れ替わるため、単独変数の警告順もそれに合わせます。
例として `$missing == (1 / 0)` は未定義変数の警告前にゼロ除算で止まり、
`$left > $right` は両方が未定義ならright、leftの順に警告します。
PHP全演算子の一般的な評価順序を保証するものではなく、対象コードの比較命令に合わせた処理です。

仕様確認には[比較の公式説明](https://www.php.net/manual/en/language.operators.comparison.php)、
[8.4.26の数値・文字列比較](https://github.com/php/php-src/blob/php-8.4.26/Zend/zend_operators.c)、
[8.5.11のNaN比較処理](https://github.com/php/php-src/blob/php-8.5.11/Zend/zend_operators.c)、
[比較命令の生成](https://github.com/php/php-src/blob/php-8.5.11/Zend/zend_compile.c)と
[実行処理](https://github.com/php/php-src/blob/php-8.5.11/Zend/zend_vm_def.h)を使用しました。
この基本型比較のfixtureは、その後のユーザー提供ログによる公式PHP比較で全3版とも一致しました。

### 真偽値変換と分岐

ifの条件と論理演算では、対応する値を次の規則で判定します。

| 型 | falseになる値 | trueになる値 |
| --- | --- | --- |
| null | null | なし |
| bool | false | true |
| int | 0 | 正負の非ゼロ整数 |
| float | 0.0、-0.0 | 非ゼロ、INF、-INF、NaN |
| string | 空文字列、正確に `"0"` の1バイト文字列 | `"00"`、`"0.0"`、`"0e0"`、空白、NULを含むその他の文字列 |
| array | 空配列 | 要素のある配列 |
| object | なし | 対応するすべてのオブジェクト |

これは[公式の真偽値変換規則](https://www.php.net/manual/en/language.types.boolean.php#language.types.boolean.casting)に基づく実装です。
NaNのif条件は3バージョンともtrueになりますが、PHP 8.5.11では変換時に警告も発生します。
Goも8.5設定時にこの警告を出し、8.3・8.4設定および既定の実行では警告を出しません。
これはPHP 8.5の仕様差として後述します。
`(bool)`キャスト自体はまだ対象外です。

`if (式) { 文... }` に続く複数の `elseif (式) { 文... }`、`else if (式) { 文... }` と
末尾の省略可能な `else { 文... }` を受け付けます。2つの綴りを混在できます。
条件の括弧は必須です。本体は波括弧付きブロックまたは単文で、空文・空ブロック・else省略・ネストに対応します。
波括弧がない場合、`else` は、まだelseが結び付いていない最も近い `if` に結び付きます。
キーワードは大小文字を区別しません。ブロックで変数スコープは増えず、選ばれた分岐内での代入は外側から参照できます。
`if: ... endif;` の代替構文は未対応です。

必要な条件を先頭から1回ずつ評価し、最初に成立した本体だけを実行します。
成立した分岐以降の条件と未選択の本体は評価せず、変数代入・出力・未定義変数警告・
NaN変換警告・ゼロ除算・型エラー・ネストした条件式は実行しません。
ただしファイル全体の構文解析は実行前に行うため、未選択側でも構文エラーや未対応構文は拒否します。

### 論理演算と短絡評価

`!` はオペランドを真偽値に変換して否定し、`&&` と `||` は次の順序で評価します。
結果は常にboolです。たとえば `false || 'text'` は文字列ではなくtrueを返します。

1. 左辺を1回評価し、既存のPHP真偽値変換を行う。
2. `&&` で左辺がfalseならfalse、`||` で左辺がtrueならtrueを返し、右辺は評価しない。
3. それ以外の場合だけ右辺を1回評価し、真偽値へ変換したboolを返す。

短絡された右辺の未定義変数警告・NaN変換警告・ゼロ除算・型エラーは発生しません。
一方、評価が必要な右辺の警告・致命エラーは通常どおり発生します。
ファイル全体を先に解析するため、短絡される右辺や未選択分岐に構文エラーがあれば実行前に失敗します。
この左辺から右辺への規則は論理演算についての説明で、PHPの全演算子の評価順序を保証するものではありません。

`!`・`&&`・`||` とifは、NaN警告を含む共通の真偽値変換処理を使用します。
NaNはtrueへ変換され、8.5設定では実際の変換ごとに警告を出します。
`!!$nan` は警告1回、`$nan && $nan` は2回、`$nan || $nan` は1回、
`false && $nan` と `true || $nan` は0回です。8.3・8.4ではこの警告を出しません。

仕様は[公式の論理演算子](https://www.php.net/manual/en/language.operators.logical.php)、
[優先順位](https://www.php.net/manual/en/language.operators.precedence.php)、
[PHP 8.5のNaN警告RFC](https://wiki.php.net/rfc/warnings-php-8-5#coercing_nan_to_other_types)と
[短絡評価のコンパイル処理](https://github.com/php/php-src/blob/PHP-8.5/Zend/zend_compile.c)で確認しました。
資料に基づいて作成した24fixtureは、その後のユーザー提供ログによる公式PHP比較でも全3版で一致しました。

`print` は対象外です。通常の関数やメソッド呼び出しを右辺に使えます。
`success/class_short_circuit_output.php` は、短絡されたメソッドの `echo`・未定義変数・ゼロ除算が
実行されず、必要な右辺だけが出力されることを検査します。このfixtureはユーザー提供ログで全3版とも一致しました。

### 配列・オブジェクト・式内代入

配列は挿入順のあるint/stringキーのマップです。`[1, 'x' => 2]` と `array(...)`、
読み書き `$a[$key]`、末尾追加 `$a[] = 値`、多段の添字、空配列・末尾カンマを受け付けます。
同じキーへの再代入は元の順序を保ちます。正規の10進整数文字列はintキーになり、
`'01'`・`'+1'`・`'-0'`・範囲外の整数文字列はstringキーのままです。
boolは0/1、nullは空文字、floatは整数へ変換し、必要な診断を出します。
負のキーからの自動採番、int64最大キーによる追加失敗、無効なキー・未定義キーもfixtureに含めます。

配列代入と引数渡しは値コピーで、書き込み時に変更経路をコピーします。
配列内のオブジェクトは同じインスタンスを共有します。`$a[] = $a` は代入前の配列値を格納します。
配列同士の `+` は左辺のキーを優先する結合です。空配列だけがfalseになります。
`===` はキー・値・型・順序、`==` はキーと緩い値比較を使い、後者では順序を問いません。
大小比較は要素数を先に比較し、同数なら対応するキーの値を比較します。
対応しないキー集合や異なるクラスのオブジェクトは全順序を作りません。
`<=>` が両方向で1になっても、`<` / `>` がともにfalseとなる組み合わせがあります。

`new stdClass`、`new stdClass()` と `$o->name` の読み書きを受け付けます。
オブジェクト代入は同じインスタンスを共有し、`===` は同一インスタンスかを判定します。
同じクラスの `==` はプロパティを緩く比較し、別クラスなら同じ値でもfalseです。
オブジェクトと数値の比較で発生するNotice、配列の文字列化警告、
オブジェクトの文字列化エラー、循環したプロパティの比較エラーも収録しています。

式内代入は値を返し、配列添字・プロパティや短絡評価と組み合わせられます。
代入先の部分式、右辺、変数読み取りの評価時点をZendのコンパイル・実行処理に合わせています。
自己代入を含む配列追加、添字と右辺で同じ変数を更新するケース、
右辺が未評価のときに代入・警告・エラーを起こさないケースをfixtureで検査します。
`[]` を読み取り式に置いた場合は、未選択側でも実行前にFatal errorで拒否します。
文字列添字は読み取りのみを実装し、書き込みは未対応として拒否します。

[配列演算](https://www.php.net/manual/en/language.operators.array.php)、
[代入](https://www.php.net/manual/en/language.operators.assignment.php)、
[オブジェクト比較](https://www.php.net/manual/en/language.oop5.object-comparison.php)、
[PHPの代入コンパイル](https://github.com/php/php-src/blob/PHP-8.4/Zend/zend_compile.c)と
[実行命令](https://github.com/php/php-src/blob/PHP-8.4/Zend/zend_vm_def.h)です。
新規の期待値はこれらから手動で決め、Goの出力から採取していません。

### 独自クラスとメソッド

継承なしの `class Name { ... }` を実装しています。プロパティは型指定なしで
`public`・`protected`・`private` または `var` で宣言し、既定値を省くとnullになります。
配列を含む、対応演算による定数式を既定値にできます。
インスタンスごとにプロパティを持ち、同じクラスのメソッドからのみ非publicメンバーへアクセスできます。
未宣言プロパティの作成は、独自クラスではDeprecated、`stdClass` では診断なしです。

`function name($a, $b = 既定値) { ... }` はpublicメソッドになり、明示的な可視性も指定できます。
位置引数、既定値、余分な位置引数の評価、引数不足のArgumentCountError、
`$this`、ローカル変数、再帰呼び出し、戻り値のチェーンを扱います。
配列引数は値コピー、オブジェクト引数は共有です。呼び出し間でローカル変数は共有せず、
呼び出し元の変数へアクセスする `global` は未対応です。
`return 式;` は呼び出しから戻り、`return;` または末尾到達はnullを返します。
クラス名とメソッド名は大小文字を区別せず、プロパティ名は区別します。

`new Name(引数...)` は宣言されたプロパティを初期化して `__construct` を呼び出します。
PHP 8.3〜8.5に合わせ、コンストラクタの戻り値は `new` では無視し、
明示的な `$o->__construct()` 呼び出しでは通常の戻り値として扱います。
トップレベルの無条件クラス宣言はその記述位置より前から使用でき、
条件分岐内のクラス宣言はその分岐が実行されたときにだけ登録します。
メソッド本体は未使用であっても、ファイル全体の字句・構文解析とコンパイル検査の対象です。

メソッド内のエラーには、呼び出し元の行・クラス・メソッド・引数を含む履歴を出します。
引数の表示は診断時の値を使い、文字列の省略・エスケープ、配列/オブジェクトの表示を扱います。
エラー後もGo内部の呼び出し元スコープを復元します。再帰呼び出しの上限は256です。

仕様確認には[クラスの基本](https://www.php.net/manual/en/language.oop5.basic.php)、
[コンストラクタ](https://www.php.net/manual/en/language.oop5.decon.php)、
[プロパティ](https://www.php.net/manual/en/language.oop5.properties.php)、
[アクセス権](https://www.php.net/manual/en/language.oop5.visibility.php)、
[引数](https://www.php.net/manual/en/functions.arguments.php)、
[変数スコープ](https://www.php.net/manual/en/language.variables.scope.php)、
[PHPのアクセス制御実装](https://github.com/php/php-src/blob/PHP-8.4/Zend/zend_object_handlers.c)を使用しました。
これらは実装時に参照した資料です。診断修正後のユーザー提供ログではクラスfixture35件が全3版で一致しました。
正常系17件の成功に加え、PHP 8.5のコンパイルエラー時のスタックトレースも一致しています。

### 代入・算術の拡充（項目4）

`+= -= *= /= %= .=`、前置/後置の `++ --`、剰余 `%` を追加しました。
複合代入は代入と同じ優先順位で右結合、`%` は `* /` と同順位で左結合です。
代入式は代入後の値、前置は更新後の値、後置は更新前の型と値を返します。
変数・配列要素・プロパティを更新でき、添字や受け手の関数/メソッド呼び出しを重複実行しません。
複合代入の右辺はPHPの遅延した書き込みと組み合わせて評価します。
未定義値の警告順序も、変数/プロパティへの代入と配列要素への代入で区別します。

算術の既存の数値変換・整数オーバーフロー処理、連結の文字列化、配列の `+` 結合を共用します。
`%` は両項を整数へ変換し、結果はintです。符号は被除数に従い、最小整数 `% -1` は0です。
実数は小数部を切り捨て、float-stringの有限オーバーフローは飽和、floatの範囲外変換は折り返します。
精度喪失・先頭のみ数値の文字列の診断、型エラー、整数変換後のゼロに対する `Modulo by zero` を扱います。
`stdClass` と独自クラスのオブジェクトは `%` / `%=` の整数変換を拒否し、TypeErrorで終了します。
数値比較のオブジェクト変換とは異なり、整数1へ変換する警告と計算結果は出しません。

数値文字列の増減はint/floatへ変換します。nullの `++` は1、boolの増減とnullの `--` は値を維持して警告します。
非数値文字列の `++` はASCII英数字の桁上がり、空文字列は文字列 `'1'` になります。
非数値文字列の `--` は値を維持し、空文字列の `--` は整数-1で、いずれも非推奨診断を出します。
PHP 8.5の非数値文字列増分の非推奨、範囲外floatからintへの警告、NaNからstringへの警告は対象設定で切り替えます。

確認資料は[代入](https://www.php.net/manual/en/language.operators.assignment.php)、
[算術](https://www.php.net/manual/en/language.operators.arithmetic.php)、
[増減](https://www.php.net/manual/en/language.operators.increment.php)、
[優先順位](https://www.php.net/manual/en/language.operators.precedence.php)、
[8.3.35の演算処理](https://github.com/php/php-src/blob/php-8.3.35/Zend/zend_operators.c)、
[8.4.26の演算処理](https://github.com/php/php-src/blob/php-8.4.26/Zend/zend_operators.c)、
[8.5.11の演算処理](https://github.com/php/php-src/blob/php-8.5.11/Zend/zend_operators.c)、
[代入命令の評価順序](https://github.com/php/php-src/blob/php-8.5.11/Zend/zend_vm_def.h)です。
資料に基づく実装・期待値をユーザー提供の337件比較で確認し、剰余のオブジェクト変換の誤りを修正しました。

### while・for・do/while（項目5・6）

3種類のループは、波括弧付きブロックと単文を扱い、相互にネストできます。
`while` は本体前、`do / while` は本体後にPHP真偽値変換で条件を検査します。
`for` は初期化を1回だけ評価し、毎回の条件・本体・更新を順に評価します。
各部分の省略とカンマ区切りの複数式に対応し、条件部は最後の式だけをboolへ変換します。
省略された条件部はtrueです。NaNを途中の式として捨てるだけの場合は、bool変換警告を出しません。

`break;` / `continue;` はレベル1です。正の整数リテラルでレベルを指定できます。
`continue` の対象となるforは更新式、do/whileは条件式を評価してから次へ進みます。
`break` では抜けたループの条件や更新を評価しません。内側から外側へレベルを伝え、
途中のループの更新・条件・残りの文を実行しないようにしています。関数のreturnもループを抜けます。

ループ外、0・負数・float/string/bool/null・変数/式によるレベル、実際のネストを超えるレベルは実行前に拒否します。
単項 `+1` / `-1` も整数リテラルそのものではなく式なので、非整数オペランドの診断です。
関数/メソッド本体ではループ深度をリセットし、呼び出し元のループをbreakすることはできません。
未選択分岐・0回ループ・break後のコードも構文解析とコンパイル検査を行います。

[forの公式説明](https://www.php.net/manual/en/control-structures.for.php)と
[8.4.26のループ・break/continueコンパイル処理](https://github.com/php/php-src/blob/php-8.4.26/Zend/zend_compile.c)を参照しました。
fixtureは0回・1回・複数回・混在ネストを扱い、省略条件のループには明示的なbreak/returnを置いています。
通常のCLI実行に独自の反復上限は設けず、比較スクリプトで各プロセスを5秒に制限します。
fuzzだけは内部の反復予算を使い、生成された無限ループで検査が停止しないようにします。

### 通常の関数と配列の連携（項目7・8）

`function name($a, $b = 既定値) { ... }` と名前による呼び出しを追加しました。
メソッドと同じ引数・戻り値・呼び出し履歴の処理を使い、位置引数、対応する定数式の既定値、
値渡し、余分な引数の評価、return、末尾到達/return値省略時のnullを扱います。
呼び出しごとにローカル変数を作り、再帰や相互再帰でもスコープを混ぜません。
通常関数には呼び出し元メソッドの `$this` やprivateアクセス権を引き継ぎません。
関数名は大小文字を区別せず、未定義関数・引数不足・重複定義を診断します。

トップレベル直下の関数宣言は記述位置より前やreturnより後でも呼び出せます。
条件分岐・ループ・他の関数の中の宣言は、実行が宣言に到達した時点で登録します。
後者を再実行すると重複定義のFatal errorになります。未使用の関数本体も実行前の検査対象です。
必須引数を省略可能引数の後に置く場合は、先行する引数も必須にし、コンパイル時の非推奨診断を出します。

既存の順序付き配列を維持し、作成・キー変換・同一キー更新・末尾追加・ネストの挙動を共用します。
代入、関数/メソッドの引数、returnでは配列を値として扱い、更新時に新しい配列を作るため別の変数へ影響しません。
配列内のオブジェクトは同じインスタンスを共有します。複合代入・増減・再帰関数・ループと組み合わせ、
元配列が変わらないこと、キーの挿入位置が維持されること、オブジェクト側の変更が共有されることを検査します。

[ユーザー定義関数](https://www.php.net/manual/en/functions.user-defined.php)と
[8.4.26の関数コンパイル](https://github.com/php/php-src/blob/php-8.4.26/Zend/zend_compile.c)、
[8.3.35の引数診断](https://github.com/php/php-src/blob/php-8.3.35/Zend/zend_compile.c)、
[8.5.11の重複定義診断](https://github.com/php/php-src/blob/php-8.5.11/Zend/zend_compile.c)を参照しました。

## 未対応

`if: ... endif;` やループのコロン構文、`foreach`、標準関数、C拡張、Webサーバー、JIT、
参照、resource、`unset`、配列の展開・分解代入、文字列添字への書き込み、動的なプロパティ/メソッド名、
継承・interface・trait、型宣言・staticメンバー・クラス定数・属性・匿名クラス・clone・名前空間・autoload、
`__construct` 以外のマジックメソッド、名前付き/参照/可変長引数、`self` / `parent` / `static` によるクラス参照、
論理演算 `and or xor`・ビット演算、累乗、キャスト、例外処理、`print`、
定数、数値の桁区切り、16/8/2進整数リテラル、heredoc/nowdocは未対応です。
既定引数内の `new`、クロージャ、変数関数、global/static変数も扱いません。
スーパーグローバル、`$argc`・`$argv`は明示的に拒否し、通常のPHP実行環境全体は作成しません。
`$this` はメソッド内で対応し、外側での参照はPHP形式のError、再代入は実行前のFatal errorです。
通常関数・メソッドを合わせた呼び出し深度は256に制限し、超過時はGo独自のErrorで停止します。これはPHPと同じ上限ではありません。

未対応構文は診断をstderrへ出し、非ゼロで終了します。
ファイル全体を解析してから実行するため、後半に構文エラーや未対応構文がある場合も前半を実行しません。
PHPの全構文・全実行環境との互換性は主張しません。

## CLI仕様と構成

```sh
make build
./bin/gophp path/to/program.php
./bin/gophp --php-version=8.5 path/to/program.php
```

引数は省略可能な対象バージョンとPHPファイルのパス1つです。
`--php-version=8.3|8.4|8.5` または `--php-version 8.5` の形式で、パスより前に指定します。
省略時は8.4、未対応の指定値は終了コード2です。`--help` で使用法を表示します。
Go側の設定はメジャー・マイナーで指定し、公式PHPの比較スクリプトには正確なパッチバージョンを指定します。
stdin、`-r`、php.ini、PHP自体のCLIオプションは扱いません。
プログラム出力はstdout、警告・エラーはstderrへ送ります。診断のパスは絶対パスです。

| 終了コード | 意味 |
| --- | --- |
| 0 | 正常終了。継続可能な警告を含む |
| 1 | ファイル読み取り・出力などのI/Oエラー |
| 2 | CLI引数エラー |
| 255 | 構文エラー・未対応構文・実行時致命エラー |

`internal/php/lexer.go` → `parser.go` → `eval.go` が処理の流れです。
`value.go` に型変換と算術、`compare.go` / `aggregate_compare.go` に比較、
`aggregate.go` に配列・プロパティ・代入、`class.go` にクラスとメソッド呼び出し、
`arithmetic.go` に複合代入・増減・剰余、`loop.go` にループとレベル制御、
`function.go` に通常関数、`validate.go` に実行前の書き込み位置・定数式・ループ深度検査をまとめています。`cmd/gophp` が標準入出力を接続します。
Go標準ライブラリのみで実装しています。

ユーザーが案内したコンテナ構成とラッパーを読み、Go側の `make test vet build` が成功した後、
このセッションから次のコマンドを実行しました。

```sh
cd /Users/kouji/dev/php/containers/php-version
./compare-all.sh tests/fixtures ./bin/gophp
```

| 期待バージョン | PHPラッパー終了コード | 結果 |
| --- | --- | --- |
| 8.3.35 | 125 | Podman接続拒否。バージョン未確認、fixture未実行 |
| 8.4.26 | 125 | Podman接続拒否。バージョン未確認、fixture未実行 |
| 8.5.11 | 125 | Podman接続拒否。バージョン未確認、fixture未実行 |

この試行の `compare-all.sh` の終了コードは2でした。3バージョンとも事前確認で停止し、
この試行では一致・不一致を判定できませんでした。接続失敗のログは [php-container-comparison.txt](../validation/php-container-comparison.txt) に保存しています。

Podmanの接続先 `127.0.0.1:60028` に対し `connect: operation not permitted` が返りました。
`check.sh` も同じ理由で終了コード125になりました。`podman machine list` はVMのロックファイルへの
アクセスが拒否され、仮想マシンの稼働状態を確認できていません。
したがって、この結果からコンテナの未作成・停止を断定することはできません。
このセッションの権限制限により、コンテナの起動や公式PHPの実行を確認する段階へ進めていません。

その後、ユーザーのターミナルではコンテナ起動と全fixtureの比較ができ、上記の結果が得られました。

### コンテナ構成が案内される前の初回試行

初回は以下の比較コマンドを実行しましたが、PHPのバージョン確認で終了コード2になりました。

```sh
python3 skills/php-go-interpreter/scripts/compare_php.py \
  --php php --php-version 8.4.0 --fixtures tests/fixtures \
  --interpreter ./bin/gophp '{file}'
```

```text
ERROR: could not verify official PHP: [Errno 2] No such file or directory: 'php'
```

この時点ではホストのPHPが見つからず、Podmanへの接続も実行環境の制限で拒否されました。
PHPソースのダウンロードは名前解決に失敗しました。その後、ユーザーが上記のPodman環境を案内しました。
